## Which integration should own the session and Git mutations?

### Takeaway

Recommendation: use an app-owned repository session and the Git CLI through asynchronous Qt QProcess, with a narrow backend interface. Prefer an initial system package for this path. Treat conventional `git mergetool` support as a separate, constrained compatibility adapter whose ownership must be specified before promising the complete PRD experience.

### Cited findings

- **Requirement.** The app must show every currently conflicted file, keep two read-only sources around an editable center, offer base context on demand, preserve text and decision undo, recover unsaved work, and distinguish Save from Mark resolved. Continuing merge/rebase and committing remain outside the app. Future desktops should use idiomatic UI kits and loose coupling, with no shared UI-code promise. [PRD](../../PRD.md), [desktop convention](../../.ai/kenkeep/nodes/practice-design-desktop-apps-around-screens-and-components.md).
- **Documented fact: process execution.** QProcess accepts a program and separate arguments; on Unix it does not automatically invoke a shell. Qt documents Unix child setup before `execve()`, asynchronous output/finish/error signals, and SIGTERM/SIGKILL through terminate/kill. This supports a nonblocking CLI adapter, not a security or process-tree guarantee. [QProcess, running a process, arguments, child modifier and cancellation](https://doc.qt.io/qt-6/qprocess.html).
- **Documented fact: terminology.** Linux `execve` replaces the calling process image and takes argv and environment arrays. A subprocess launch is a higher-level operation involving child creation, descriptor setup, execution, and supervision. A shell is a command-language interpreter introduced explicitly, such as `/bin/sh -c`. Calling Git via QProcess is subprocess execution through OS facilities; it is neither a Git-specific syscall nor necessarily shell execution. [Linux man-pages project's execve manual](https://man7.org/linux/man-pages/man2/execve.2.html).
- **Documented fact: libgit2 bindings.** pygit2 binds the libgit2 shared library; Rust's git2 binds the C library and adds typed interfaces and resource management. Neither is pure Rust Git. Python can therefore choose pygit2, and Rust can choose git2, without making Qt or any frontend mandatory. [pygit2 introduction](https://www.pygit2.org/), [git2 crate introduction](https://docs.rs/git2/latest/git2/).
- **Documented fact: available index operations.** pygit2 exposes optional ancestor/ours/theirs entries through `Index.conflicts`, plus add and write. git2 exposes conflicts, stage lookup, add_path, conflict removal, and write. libgit2's add_bypath resolves that path's conflict into resolve-undo information; its index_write uses an atomic file lock. This is sufficient evidence of relevant primitives, not of identical behavior to installed Git. [pygit2 index](https://www.pygit2.org/index_file.html), [git2 Index](https://docs.rs/git2/latest/git2/struct.Index.html), [libgit2 add_bypath](https://libgit2.org/docs/reference/main/index/git_index_add_bypath.html), [versioned libgit2 index_write](https://libgit2.org/docs/reference/v1.9.7/index/git_index_write.html).
- **Documented fact: filters need comparison.** pygit2 documents registered Python filters and built-in CRLF/ident filters. libgit2 documents its filter pipeline. These APIs do not establish automatic parity with every Git-configured external clean/process filter, Git LFS installation, or working-tree encoding. Git's attributes manual contains an explicitly dated 2018 warning about alternative implementations and encoding; do not turn that historical warning into a verified 2026 blanket claim. [pygit2 filters](https://www.pygit2.org/filters.html), [libgit2 filter APIs](https://libgit2.org/docs/reference/main/filter/index.html), [Git working-tree-encoding and filters](https://git-scm.com/docs/gitattributes).
- **Documented fact: gix capabilities and limits.** gitoxide identifies itself as pure Rust. gix exposes repository, objects, index and merge-related APIs with a repository/config trust model. Its upstream capability checklist distinguishes available low-level index/status/diff plumbing from incomplete wider workflow composition, and labels itself generated material requiring reconciliation. Missing full merge/rebase orchestration does not disqualify reading an already-conflicted repository. [upstream gitoxide repository](https://github.com/GitoxideLabs/gitoxide), [gix trust model](https://docs.rs/gix/latest/gix/), [Repository API](https://docs.rs/gix/latest/gix/struct.Repository.html), [upstream capability checklist](https://raw.githubusercontent.com/GitoxideLabs/gitoxide/main/crate-status.md).
- **Documented fact: concrete gix write obligation.** `gix_index::File::write` acquires a lock, but the consulted API explicitly says it serializes tree-cache as-is. After modifying entries, callers should remove that cache before writing or later tree construction can use stale data. Stage-specific entry access is available. This is a current documented caveat to recheck against a pinned release, not evidence that all gix writes are corrupt. [gix-index File write and tree-cache warning](https://docs.rs/gix-index/latest/gix_index/struct.File.html#method.write).
- **Documented fact: mergetool inputs and exit contract.** A configured `mergetool.<tool>.cmd` is evaluated by a shell. `$BASE`, `$LOCAL`, `$REMOTE` name temporary ancestor/current/other inputs; `$MERGED` names the result destination. With `trustExitCode=true`, the tool's exit status determines success. Without it, timestamp checking and possibly a user prompt determine success. `hideResolved` can alter the source inputs. [Git mergetool protocol and configuration](https://git-scm.com/docs/git-mergetool).
- **Source fact: mergetool owns more than launching a GUI.** In the inspected tag, Git prepares stage inputs, optionally rewrites LOCAL/REMOTE with hideResolved, loops through paths, restores BACKUP over MERGED when the tool fails, and calls `git add -- "$MERGED"` after success. Delete/symlink/submodule cases have separate handling. Its zero return after the add call also means adapter exit success alone is inadequate evidence of staging success. [Git v2.56.0 mergetool source, merge_file and main](https://raw.githubusercontent.com/git/git/v2.56.0/git-mergetool.sh).
- **Documented fact: merge driver differs.** A merge driver participates in Git's merge machinery, receives `%O`, `%A`, `%B`, writes `%A`, and reports clean merge versus conflict by status. A mergetool is the interactive resolution step after conflicts exist. Installing Branch Truce as a merge driver would change when and how it runs. [Git custom merge driver contract](https://git-scm.com/docs/gitattributes#_defining_a_custom_merge_driver).

### Inferences

- **Recommendation, CLI first.** This app needs to inspect an existing conflict and stage selected reviewed files, not implement rebase or commit. Installed Git keeps those operations with the user's Git implementation and its configured conversions. QProcess avoids adding a C binding solely for a small operation set. The costs are process startup, byte-oriented protocol parsing, version differences, and supervising helpers. No latency result has been measured. The libraries above remain credible alternatives when the application language and compatibility requirements are decided. [Git add semantics](https://git-scm.com/docs/git-add), [QProcess](https://doc.qt.io/qt-6/qprocess.html).
- **Recommendation, separate responsibilities.** Keep Git discovery/blob retrieval/staging behind a backend interface. Put correspondence, word diff, source identity presentation, region decisions, undo, and recovery in application logic. None of the index APIs supplies the PRD's text-plus-decision model. This also permits future idiomatic frontends without promising cross-platform UI reuse. [PRD interaction requirements](../../PRD.md), [desktop convention](../../.ai/kenkeep/nodes/practice-design-desktop-apps-around-screens-and-components.md).
- **Protocol mismatch.** A conventional mergetool invocation represents one file. Returning zero on Save would let the parent stage an unfinished draft. Returning nonzero on Save-and-close can let the parent overwrite it with the pre-tool backup. A successful launcher that detaches from the GUI has the same early-success problem. Setting trustExitCode true is necessary for an explicit adapter contract but does not solve draft persistence or all-files ownership. [mergetool manual](https://git-scm.com/docs/git-mergetool), [versioned mergetool source](https://raw.githubusercontent.com/git/git/v2.56.0/git-mergetool.sh).
- **Recommendation, direct repository launch.** Launch Branch Truce with an explicit repository/worktree context from the user's existing workflow, enumerate the conflict set once, and let Branch Truce own Save and per-file staging. This satisfies the required all-files session without an enclosing mergetool process independently deciding when to stage or restore. This proposal still needs confirmation that direct launch meets the intended meaning of "usable as a Git merge tool." [PRD](../../PRD.md), [desktop convention](../../.ai/kenkeep/nodes/practice-design-desktop-apps-around-screens-and-components.md).
- **If a conventional adapter is required.** Specify a separate four-file mode, block until the addressed file is deliberately resolved, persist recovery outside ephemeral mergetool files, and make cancellation consequences explicit. If Git owns staging in that mode, Mark resolved must wait for acknowledged parent staging before displaying a confirmed outcome. An all-files coordinator would need a custom launcher/IPC protocol, protection against the parent's later stale path invocations, and one staging owner per file. Do not claim ordinary `.cmd` registration supplies this. Set hideResolved false or obtain faithful source snapshots independently. [mergetool protocol](https://git-scm.com/docs/git-mergetool), [versioned orchestration source](https://raw.githubusercontent.com/git/git/v2.56.0/git-mergetool.sh).

### Gaps

- Must first release work as `git mergetool --tool=branch-truce`, or is a repository-session launcher sufficient? The requirement calls for existing-workflow launch but does not specify this protocol. This choice affects architecture, not just argument spelling. [PRD](../../PRD.md).
- Python, C++, Rust, UI framework, minimum Git version, distributions, licensing review, and measured process overhead remain undecided. The available upstream APIs establish feasibility, not the winning language or UI kit. [pygit2](https://www.pygit2.org/), [git2](https://docs.rs/git2/latest/git2/), [gix](https://docs.rs/gix/latest/gix/), [QProcess](https://doc.qt.io/qt-6/qprocess.html).

## How should discovery, saving, staging, and execution stay constrained?

### Takeaway

Use machine-readable Git state and immutable source snapshots. Restrict mutations to explicitly reviewed paths, distinguish working-file saves from index updates, and stop writes on stale preconditions. Shell-free argv removes one injection route; it does not sandbox Git, repository configuration, helpers, or filesystem races.

### Cited findings

- **Documented fact: stages.** Git revisions support `:0:path`, `:1:path`, `:2:path`, `:3:path`. Stage 0 is the ordinary index entry; 1 is ancestor, 2 target/current side, 3 the other side in a merge. During merge-based rebase, ours is the accumulated rebased series and theirs the replayed working-branch contribution. [Git revision syntax](https://git-scm.com/docs/gitrevisions#_specifying_revisions), [Git rebase ours/theirs explanation](https://git-scm.com/docs/git-rebase).
- **Documented fact: machine discovery.** `ls-files --unmerged --stage -z` returns modes, object IDs, stages and verbatim NUL-terminated paths. Not every conflict has every stage. Porcelain v2 `u` records contain conflict type, modes and three stage IDs; other records cover ordinary and renamed paths. `-z` preserves unusual names and uses an additional NUL-separated original path for rename records. [Git ls-files output](https://git-scm.com/docs/git-ls-files#_output), [Git status porcelain v2](https://git-scm.com/docs/git-status#_porcelain_format_version_2).
- **Documented fact: repository locations.** rev-parse exposes show-toplevel, git-dir, git-common-dir, git-path and gitfile resolution. `--git-path` accounts for relocation variables including GIT_INDEX_FILE. A worktree's administration must not be assumed to be a physical `<root>/.git` directory. [Git rev-parse file/location options](https://git-scm.com/docs/git-rev-parse).
- **Documented fact: blobs.** cat-file reads objects, reports type/size and supports batched access. Textconv and worktree filters are explicit modes. Raw object retrieval therefore offers a way to obtain source bytes without requesting those conversions. [Git cat-file modes](https://git-scm.com/docs/git-cat-file).
- **Documented fact: path interpretation.** Git's global literal-pathspecs option disables glob/pathspec magic. `--` separates options from paths; it does not itself turn patterns literal. Git also documents no-pager, no-optional-locks, no-replace-objects and no-lazy-fetch controls. No-lazy-fetch matters for offline access to missing promisor objects. [Git command and environment reference](https://git-scm.com/docs/git).
- **Documented fact: staging.** Git add records current working-file content in the index; later edits require another add. It supports pathspec input from stdin with NUL separators. Thus staging a file is not just toggling a resolved flag, and it stages that file's full current content rather than only the GUI's selected regions. [Git add description and pathspec input](https://git-scm.com/docs/git-add).
- **Documented fact: execution through configuration.** core.fsmonitor can name an executable hook. core.hooksPath can redirect hooks or disable them using `/dev/null`. safe.directory is an ownership trust gate, with `*` disabling that check. It does not certify repository content. [Git configuration reference, these specific keys](https://git-scm.com/docs/git-config).
- **Documented fact: git add subtleties.** Clean/process filters may execute programs and change worktree bytes into stored bytes; process takes precedence over clean/smudge. Git's hook reference includes post-index-change on index writes. `git add` does not mean "runs pre-commit", since pre-commit belongs to commit, but "git add never executes hooks" is also incorrect. [Git attributes filter contract](https://git-scm.com/docs/gitattributes#_filter), [Git hook invocation contracts](https://git-scm.com/docs/githooks#_post_index_change).
- **Documented fact: diff helpers.** `--no-ext-diff` disables external diff drivers; `--no-textconv` disables text conversion helpers. A diff exit code of 1 can mean differences rather than failure. [Git diff external helpers and exit status](https://git-scm.com/docs/git-diff).
- **Documented fact: file replacement and races.** QSaveFile writes a temporary file and commits by replacement; enabling directWriteFallback loses atomic-replacement protection. Linux pathname lookup documents concurrent rename and symlink complications. Git lockfiles exclude competing writers during a particular update; they do not lock readers or a whole editor session. [QSaveFile](https://doc.qt.io/qt-6/qsavefile.html), [kernel pathname lookup](https://docs.kernel.org/filesystems/path-lookup.html), [Git lockfile API source](https://raw.githubusercontent.com/git/git/v2.56.0/lockfile.h).
- **Documented fact: text/path representation.** QFile defaults to binary I/O unless text mode is requested; QTextStream defaults to UTF-8. Qt file paths use QString, and QFile's encodeName uses UTF-8 on Linux. This deserves explicit validation for Linux filenames containing invalid UTF-8, separate from file-content encoding. [QFile encoding and platform notes](https://doc.qt.io/qt-6/qfile.html).

### Inferences

The following is a proposed contract for the recommended backend, not implementation already present.

1. **Capture a worktree-specific session.** Discover the selected worktree root and actual Git/index locations. Record repository identity, operation kind and relevant commit identities, conflict entries and modes, initial working-file identities/content hashes, and selected Git executable. Enumerate all conflicts using unmerged index records; use porcelain for supplementary context. Preserve unsupported delete/rename/binary/symlink/gitlink cases visibly. Conflict discovery alone is not a complete historical rename classifier, so ambiguous identity stays unsupported. Do not derive source meaning only from branch names, which may be absent in rebase. [rev-parse](https://git-scm.com/docs/git-rev-parse), [ls-files](https://git-scm.com/docs/git-ls-files), [PRD](../../PRD.md).
2. **Keep source data stable.** Read validated object IDs with `cat-file blob <oid>`, or initially one process per blob; use size checks and streaming limits. Batch later if measured overhead warrants it, parsing the documented length-framed protocol. Store byte snapshots and mode/encoding metadata before stage entries disappear. Missing ancestor, an empty ancestor, missing objects, and unreadable objects are distinct outcomes. Do not parse conflict markers as the authority for original versions. [cat-file](https://git-scm.com/docs/git-cat-file), [index stages](https://git-scm.com/docs/gitrevisions).
3. **Separate raw Git representation from editor representation.** Decode supported text deliberately and preserve final newline, BOM, line endings and permissions. Raw blobs can differ from worktree bytes after Git conversions. Choose whether to support a conversion reproducibly or mark it outside first-release support; do not quietly run smudge/textconv or save a normalized editor buffer as though bytes were preserved. [Git attributes](https://git-scm.com/docs/gitattributes), [QFile](https://doc.qt.io/qt-6/qfile.html), [PRD reading requirements](../../PRD.md).
4. **Save touches the result file only.** Verify the target still matches the last known baseline, retain recovery state, write the reviewed buffer using validated replacement semantics, and update the saved baseline only after success. Leave unmerged entries untouched. QSaveFile is a candidate mechanism, not a complete answer for symlinks, metadata preservation, durability, or concurrent replacements. Keep direct-write fallback disabled for this path. [QSaveFile](https://doc.qt.io/qt-6/qsavefile.html), [Save convention](../../.ai/kenkeep/nodes/practice-separate-save-from-mark-resolved.md).
5. **Mark resolved saves, then stages one exact path.** Confirm undecided choices as required by the PRD. Revalidate the operation, index stages and output; Save; invoke selected Git with literal pathspecs and `add -- <repo-relative-path>`. For arbitrary filename bytes, NUL-delimited stdin pathspecs avoid a lossy QString argv conversion, but file I/O still needs a byte-safe path strategy. Never use add-all, commit, rebase-continue, reset, checkout or a whole-session index replacement as the normal resolution action. Verify the target now has expected stage-0 state and no unmerged stages; preserve unrelated staged entries. A successful command is necessary evidence, not sufficient evidence after hooks or races. [Git add](https://git-scm.com/docs/git-add), [QFile](https://doc.qt.io/qt-6/qfile.html), [failure convention](../../.ai/kenkeep/nodes/practice-keep-failed-work-outstanding.md).
6. **Keep staged and saved bytes conceptually distinct.** With enabled clean filters, stage 0 may legitimately differ from the saved worktree bytes. Verification must account for the declared conversion rather than demand raw byte equality. If saving succeeds but staging fails, retain "saved, unresolved". After a crash/cancel/ambiguous result, inspect real index state before reporting or retrying; do not infer unchanged state from a failed child process. [filter contract](https://git-scm.com/docs/gitattributes#_filter), [post-index-change](https://git-scm.com/docs/githooks#_post_index_change), [PRD failures](../../PRD.md).
7. **Constrain spawning.** Use a trusted absolute Git binary, explicit worktree cwd and program-plus-argv. Keep subcommands/options fixed by the application. Never interpolate file paths into a shell, feed them as options, or execute a command supplied by a repository. Deliberately build the environment, removing or explicitly adopting inherited repository/index/object redirects, config injection, external-diff, pager, loader and helper search settings. Preserve legitimate user configuration only under a stated trust policy. Use literal pathspecs as well as `--`. These constrain known interpretation routes; they are not a sandbox. [QProcess arguments](https://doc.qt.io/qt-6/qprocess.html), [Git environment/options](https://git-scm.com/docs/git).
8. **Choose execution policy per operation.** Discovery should disable optional index writes, fsmonitor helpers and hooks, avoid external diff/textconv, disable pagers, and prevent lazy fetching on supported Git versions. For staging, decide whether normal user filters/hooks are trusted or unsupported. A restricted mode can use per-command hooksPath and fsmonitor overrides, but disabling hooks does not disable filters, and disabling filters can silently produce wrong repository content. Do not globally modify user config or set safe.directory to `*`. No evidence here supports a universal "safe to open any repository" claim. [configuration controls](https://git-scm.com/docs/git-config), [diff controls](https://git-scm.com/docs/git-diff), [filters](https://git-scm.com/docs/gitattributes).
9. **Protect paths separately from argv.** Accept paths discovered in the session; reject absolute paths, traversal and reserved administration destinations; validate component boundaries, regular-file modes and directory identities. Resolve/recheck symlinked parents and target links before writes. A string-prefix or one-time realpath check does not prevent later symlink replacement. Investigate descriptor-relative constrained filesystem operations for stronger Linux containment. Git metadata for linked worktrees may legitimately live outside the worktree root, so result-file containment and repository metadata access need different rules. [kernel pathname lookup](https://docs.kernel.org/filesystems/path-lookup.html), [rev-parse](https://git-scm.com/docs/git-rev-parse).
10. **Bound and supervise work.** Drain stdout and stderr asynchronously and separately; cap retained diagnostics, blob sizes, record counts, total session bytes and elapsed work. On overflow, fail the operation explicitly, never accept a truncated conflict list as complete. Use cancellation with a grace period then escalation. Plan and test descendant/helper cleanup separately; QProcess terminate/kill documents the process, not all descendants. A killed staging operation requires state inspection, and no automatic removal of an unfamiliar index.lock. [QProcess](https://doc.qt.io/qt-6/qprocess.html), [Git lockfile API](https://raw.githubusercontent.com/git/git/v2.56.0/lockfile.h).

### Gaps

- **Trust policy.** Decide whether first release supports only user-trusted local repositories and configured helpers, refuses executable filters, or offers explicit restricted support. A secure spawn policy and an execution sandbox are different engineering commitments. Arbitrary helpers can perform their own I/O or network access even if Branch Truce never invokes fetch. [filter programs](https://git-scm.com/docs/gitattributes#_filter), [Flatpak isolation](https://docs.flatpak.org/en/latest/sandbox-permissions.html).
- **Edited-after-resolution semantics.** The PRD requires a later edit to lose misleading resolved/reviewed status. Git may retain the previously staged stage-0 version while the worktree changes. Decide whether to show "Git staged previous version; current edit needs review" or explicitly restore unmerged index stages. The latter is another mutation needing careful scope and race policy; it is not ordinary editor undo. Do not promise automatic restaging or unresolving without specifying it. [PRD](../../PRD.md), [Git add snapshot semantics](https://git-scm.com/docs/git-add), [libgit2 conflict mutation API example](https://www.pygit2.org/index_file.html).
- **Input limits.** Encoding, invalid-UTF-8 names, sparse/split indexes, SHA-256 repositories, partial clones with unavailable objects, mode changes and merge rename classification need pinned-version fixtures before declaring support. gix's checklist and Git's dated alternative-client encoding warning are insufficient evidence for blanket compatibility or incompatibility. [gix checklist](https://raw.githubusercontent.com/GitoxideLabs/gitoxide/main/crate-status.md), [Git attributes](https://git-scm.com/docs/gitattributes), [QFile](https://doc.qt.io/qt-6/qfile.html).

## What must packaging, recovery, and fixture validation settle?

### Takeaway

Recommend the system-package-plus-installed-Git path first, subject to the eventual distribution choice. Flatpak changes executable, repository and helper visibility and requires a specific design. Excluding external-change reconciliation from the product does not remove the need to reject stale saves and recover honestly after partial operations.

### Cited findings

- **Requirement.** Recovery restores unsaved text and outstanding decisions while preserving unsaved/unresolved status. External-change detection with a reconciliation comparison is outside first release. [PRD recovery and scope](../../PRD.md), [recovery convention](../../.ai/kenkeep/nodes/practice-recover-unfinished-work-without-changing-its-status.md).
- **Documented fact: Flatpak environment.** A default Flatpak sandbox has limited host file, process, network and D-Bus access. File chooser portals grant access to selected resources. Host operating-system paths and sandbox runtime paths differ; host filesystem permissions do not make the runtime's `/usr` the host `/usr`. [Flatpak sandbox permissions and filesystem access](https://docs.flatpak.org/en/latest/sandbox-permissions.html).
- **Documented fact: host execution.** `flatpak-spawn --host` runs unsandboxed on the host and requires access to the org.freedesktop.Flatpak D-Bus interface. The command also supports explicit directory, environment, descriptor forwarding and watch-bus controls. It is a host-execution boundary, not an ordinary subprocess remaining under the application's sandbox. [Flatpak spawn command reference](https://docs.flatpak.org/en/latest/flatpak-command-reference.html#flatpak-spawn).

### Inferences

- **Recommendation, system package first.** A system package using a selected host Git avoids introducing a separate sandbox Git/helper/config environment for the first repository integration. Pin supported Git behavior and test distributions; distribution packages still differ. A host process runs with user privileges and is not sandboxed merely because QProcess launched it. [QProcess](https://doc.qt.io/qt-6/qprocess.html), [Git environment/config](https://git-scm.com/docs/git).
- **Flatpak alternative A, Git inside sandbox.** Bundle/select Git and its required runtime dependencies, grant repository access including linked-worktree metadata and external object locations, and define config/filter/helper availability. A portal grant for one result file is not evidence of access to its entire Git repository. Filters depending on host-only binaries or services can fail. A sandbox can limit helpers' access, but granted filesystem scope and permissions determine the actual boundary. [Flatpak permissions](https://docs.flatpak.org/en/latest/sandbox-permissions.html), [Git repository-location controls](https://git-scm.com/docs/git-rev-parse).
- **Flatpak alternative B, host Git.** A carefully constrained host bridge can retain host Git and helper behavior, but must preserve argv, cwd, byte paths, streaming, status and cancellation across the bridge. Portal-visible paths may not identify the same host pathname. Host helpers run outside the sandbox and may have broader access than the UI. A generic host-spawn permission must not be presented as confinement of Git. [Flatpak spawn](https://docs.flatpak.org/en/latest/flatpak-command-reference.html#flatpak-spawn), [Flatpak permissions](https://docs.flatpak.org/en/latest/sandbox-permissions.html).
- **Minimum stale-state protection, proposed.** Immediately before Save or Mark resolved, compare recorded worktree identity, operation identity, expected current index baseline and current target baseline. Preserve the original stage tuple separately and advance the expected baseline after the app verifies its own mutation. Detect external resolve/abort/continue, worktree replacement and changed targets; stop and retain the buffer/recovery copy. Offer safe exit/export or re-opening against current state, without implementing the excluded automatic comparison/reconciliation flow. Preflight plus postflight checks narrow races, but CLI subprocesses cannot make the whole save-and-stage sequence atomic against another writer. [PRD scope](../../PRD.md), [Git writer locking](https://raw.githubusercontent.com/git/git/v2.56.0/lockfile.h), [kernel path races](https://docs.kernel.org/filesystems/path-lookup.html).
- **Recovery storage, proposed.** Journal source snapshots or retrievable stable IDs, output bytes, decisions, saved baseline, review state and pending Save/Mark-resolved operations in app-owned durable storage. Include repository plus individual worktree identity and operation fingerprint. Reopening must validate them before applying recovery; stale recovered content should remain available without overwriting current repository files. Store app snapshots independently of mergetool temporary filenames. Define discard tombstones so discarded recovery cannot reappear. Crash durability and multi-file journal consistency need explicit verification beyond QSaveFile's replacement API. [recovery requirements](../../PRD.md), [QSaveFile scope](https://doc.qt.io/qt-6/qsavefile.html), [mergetool temporary inputs](https://git-scm.com/docs/git-mergetool).

Recommended fixture work, to be performed later in disposable repositories. No repository Git operations or tests were run for this research.

### Gaps

- Final integration choice depends on the launch contract, configured-helper policy and package format. Recommendation remains Git CLI via QProcess in an app-owned all-files session; bindings remain alternatives, and neither latest-version claims nor speed/popularity claims are established.
- Minimum Git/Qt versions need feature checks against distribution packages. Rolling documentation is evidence of an API contract at consultation, not proof an older package supports every flag. Decide fail-closed behavior for unavailable controls, particularly offline missing-object handling. [Git option reference](https://git-scm.com/docs/git), [QProcess API](https://doc.qt.io/qt-6/qprocess.html).
- Define the first release's exact support envelope for text encodings, transformed files, invalid filename bytes, rename identification, partial repositories and concurrent writers. Define what user-visible state means after editing a staged resolution. These are requirements/specification decisions to resolve before implementation, not reasons to silently broaden PRD scope. [PRD](../../PRD.md), [Git add snapshot behavior](https://git-scm.com/docs/git-add).
