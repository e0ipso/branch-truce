# Journey acceptance checks

`JourneyAcceptanceTests.cpp` checks the observable acceptance examples in `PRD.md` through the real application. Each journey creates a disposable Git repository, stops a real merge or rebase on conflicts, opens it with `SessionLoader::openRepository` and loads the real `BranchTruce` `Main` scene. The test then drives that scene with mouse clicks and key events and compares what it shows with the repository and the Git index.

## Running it

From a configured desktop build:

```sh
cmake --build build/desktop --parallel 2 --target branch_truce_journey_acceptance_tests
ctest --test-dir build/desktop -L acceptance --output-on-failure
```

Three CTest entries run the journeys, each with the label `acceptance`: `acceptance.journeys-review` (panes, choices, editing, search and Save), `acceptance.journeys-handoff` (the handoff, startup recovery and mergetool journeys) and `acceptance.journeys-window` (window fit, first undecided region, hand edits, line choices inside one conflict and the close guard). Each passes its group name as the only argument, and the binary with no argument runs every journey. Any other argument exits with status 2. CTest sets `QT_QPA_PLATFORM=offscreen` and `QT_QUICK_BACKEND=software`, and for `acceptance.journeys-window` also `QT_QUICK_CONTROLS_STYLE=org.kde.desktop`, the style the app selects at startup. To run the binary directly, set those variables yourself. It exits with status 2 on any other platform plugin. Each entry has a CTest timeout of 120 seconds. The old timing observations predate the redesigned scene and are not current measurements. Keep each timeout at least twice the slowest measured run when the final gate obtains new timings.

The process sets up its own environment before Qt starts. It uses a private `HOME`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`, `XDG_DATA_HOME` and an owner-only `XDG_RUNTIME_DIR` under one temporary directory, so the recovery store and the mergetool socket never touch the real ones. `PATH` starts with a `git` wrapper that logs every argument the app passes and refuses `fetch`, `pull`, `push`, `clone`, `ls-remote`, `remote`, `submodule` and `credential`. Each fixture repository has an unreachable `origin` remote, and the HTTP proxy variables point at a closed local port. The fixtures call `/usr/bin/git` directly, so the log holds only the app's commands.

`tests/fixtures/QuickScene.h` holds the offscreen helpers that this suite shares with `tests/app/ComparisonViewTests.cpp`. They are `settle`, `visualItem`, `accessibleName`, `namedButton`, `popupRoot`, `waitForStable`, `waitForLayout`, `clickItem` and the wrap and whitespace probes.

## Locating controls

Tests identify named controls through `objectName`; labels and accessible names remain part of the user-facing contract. Per-range actions use `choiceAccept-<id>`, `choiceIgnore-<id>`, `choiceResolve-<id>`, `choicePreviewLeftFirst-<id>` and `choicePreviewRightFirst-<id>`. `scopedChoices` contains the two source choice lanes. Each range's first row has compact inward Accept/Ignore controls while its owner is undecided and available. Precise line actions, Resolve using this side and both explicit combination orders live in `choiceMore-<owner id>`. `choiceMenu-<owner id>` is a menu-only control for a still-undecided range whose section cannot take the primary action; it is not the target for a fully decided range.

The menu title identifies the actual source range, and line entries keep their own exact scope IDs, including on a section's first line. When a section and every precise line are decided, its persistent controls disappear. The source editor remains the menu anchor. Its intended entry points are right-click or hold on a source line, and Menu or Shift+F10 at the source cursor. `SourceContextMenuHost` provides right-click and keyboard routing in the source; those routes and hold still need runtime verification. Editor controls are `stage2Text` and `stage3Text`, and the ordinary source menus are `stage2ContextMenu` and `stage3ContextMenu`. Unavailable range choices remain unavailable, while shared Undo/Redo, Copy and Select all remain inspectable as appropriate.

`clickChoice` uses a reachable section button for a primary section action. Precise line actions, including later lines, and decided ranges open the source editor's real context menu at that line. Section ownership matches side, section identity and the containing source range. `sourceLineMenu` supports right-click, Menu and Shift+F10; entries are located through the live visual tree after layout. The maintained native replay also exercises these three public gestures and Undo/Redo control lifecycle. Touch hold, composition and real assistive-technology behavior remain independent obligations. All newly authored routes await fresh CI execution.

A button the scene cannot name, such as a dialog's standard OK, Cancel or Apply button or a combo box entry, is found by its accessible name instead. `namedButton` tries the `objectName` first and the accessible name second. `accessibleName` returns `Accessible.name`, or else the button's or label's text, which is the name Qt gives assistive technology when none is set. `clickDialogButton` searches the dialog's whole item tree from `popupRoot`, so a footer that is not a plain `DialogButtonBox` works too.

Assert state through properties, not labels. The file-list toggle exposes `checked` and keeps the accessible name "Show file list" while its text changes. The historical `undecidedCounter` object name now identifies the session toolbar's conflict counter; source-decision counts are independent. Source identity locators expose the complete literal identity and accessible description, while visible role and hash segments have `Role` and `Hash` suffixes. Result gutters show one state glyph beside the line number; test provenance through its inspection data, not an extra letter column. Resolved file rows use positive status only after verified staging, and newer drafts retain their outstanding state.

The window-fit journey requires non-empty accessible names for controls in `mainControls`, including previous/next file commands. At 1280x720 it must establish eight visible text rows per pane and reachability of controls and opened menu entries. At 1280x800 it must also retain the sidebar's one-line path/status rows and handoff whole-word requirements. Toolbar overflow must be opened and its real entries checked inside the window. Choices occupy the source-edge lanes and add no separate row above the panes. Reading bars and notices consume actual height; work-area overflow uses the page's native scroll bar. Measure rendered geometry after layout rather than converting a grid-unit formula into a claimed fit. The strict-960x540 fit waiver does not relax either 1280 obligation. These are final-gate requirements, not runtime results. `fileToolbarControl` searches reachable native buttons and overflow entries, rejecting hidden measurement delegates. Save and Mark resolved also retain explicit direct prominence assertions at both strict sizes.

Regression journeys outside the PRD table:

- `a resolved mergetool handoff drops the waiting text` runs real `git mergetool` on one of two paths. Git starts this test binary with `--mergetool`, and `main()` then runs the real launcher code against the session in the test process. While Git waits, the path it has not launched says "Waiting for Git to launch this path. It is not resolved." After Mark resolved, Git exits 0 and stages the result. The resolved file then shows no waiting text, and neither does the same file after a later edit leaves the earlier result staged. The other path still shows the text.
- `clicking the launched path again after Git attached` selects one of two paths and runs real `git mergetool` on it. Once Git waits on that path, a click on the other file's row shows "Waiting for Git to launch this path" and hides Leave unresolved. A second click on the launched path's row shows the waiting text "Git is waiting on this path" and an enabled Leave unresolved again. Clicking Leave unresolved ends `git mergetool` with a nonzero status, restores the launched file's bytes and leaves both paths unmerged.
- `a 1280x720 logical screen fits the window` opens five conflicted files, including a binary file, and an outside-app warning. Its strict obligations remain eight-row pane height and reachable controls/menus at 1280x720 and 1280x800, plus sidebar no-wrap rows and handoff whole-word text at 1280x800. The choice lanes must not reduce pane height; the relevant checks also include 1500x1040. Only strict 960x540 fit has the owner's temporary waiver. The separate first-undecided-region journey retains its 960x540 coverage. At 1600x1200 the page must not scroll. These logical offscreen sizes do not establish output scaling or native fit. The migrated helpers and preserved strict assertions await fresh CI results; [platform validation](../../docs/platform-validation.md#redesign-evidence-still-required) separates historical scaled-container observations from the required native evidence.
- `a choice clears hand edits on a line deleted in the editor and on text an edit left unchanged` starts from a result the user set to the left side, where one section changes two lines. Deleting one of them in the editor leaves its region marked as hand-edited with no result range. Accepting the section previews the replacement of the hand edit, puts the line back and clears every mark, and Undo and Redo walk both states. Typing a character and deleting it marks a region without changing the text. Choosing Preview whole file from Left from the Source choices menu again keeps the text and decisions, clears the mark, and is one undo step.
- `lines from both sides of one multi-line conflict keep their text, decisions and undo` covers PRD.md:49. It starts from a result the user set to the common version, where both sides change the same three lines. Every left and right line inside that conflict can be chosen, and each one's result range is the result line at its own index. Accepting the middle left line and then the last right line previews and replaces only those launch lines. Ignoring the first left line keeps the text. Undo walks back through the text and decisions together, and redo replays them.
- `closing with input recovery could not keep asks to retry, and cancel keeps the window open` holds the recovery journal lock from the test, so the recovery commit for a typed character fails and the input stays pending. Closing the window then opens the `recoveryCloseDialog` prompt instead of the handoff. Cancel keeps the window open, and Retry while the lock is still held keeps the input pending and the window open. Once the lock is released, Retry keeps the input and the close goes on to the handoff. After Leave, the repository is unchanged and a new window restores the retried input.

Every journey also runs `checkOffline`. It asserts that the guard saw no network command, that the app ran local `rev-parse` and `cat-file`, and that no visible text in the scene mentions signing in, logging in, registering, an account, a subscription, a payment or a license key.

PRD examples 4 (whole-file and bulk choices), 11 (crash recovery) and 15 (merge-tool cancellation) are outside this suite's coverage.

## Environment-dependent gaps

- The suite uses the offscreen platform with the software Quick backend. It does not check a real Wayland or X11 session, KDE themes, scaling, input methods on a physical keyboard, accessibility metadata seen by assistive technology, or the colours of focus and progress indicators. TECH_SPEC.md:227 leaves those to packaged-application checks on the target desktops.
- A `git` wrapper on `PATH` plus proxy variables stands in for having no connection. No network namespace is involved, so a direct socket opened by Qt or a library would not be caught.
- Scrolling inside the handoff dialog and the scoped-choice list sets the view position directly instead of sending wheel events. The search scope is changed with real clicks on the combo box and its popup.
- The write-failure journey makes a directory read-only. Root ignores directory permissions, so that step fails when the suite runs as root.
- Apart from the recovery commit that the close guard journey makes fail by holding the journal lock, a failed draft save, a file that cannot open, and leave refused because of pending input or a running resolution need fault injection, so this suite does not provoke them. They are covered in `tests/app`: `Save and discard controls keep the app baseline and retry a failed Save`, `failed placeholder recovery keeps captured files visible blocks editing and retries the captured state`, and `leave refuses unrecovered input and a running resolution and finish waits for a clean handoff`.
- With Git's raw conflict output as the result, Accept and Resolve using this side change only decisions, because both sides' lines are already in the result. Known conflict markers then block Mark resolved. The choice journey starts from a result that the user had set to the common version before launch, so the text changes it checks can be seen.

The native CI runner attaches available originals, snapshots, named-region geometry, exact close-ups, comparison reports and measured residuals in `native/acceptance-ledger.json`. No automatic capture, zero-difference repeat, passing CTest or successful package lifecycle approves a callout.

The KDE matrix retains its CTest, warning-free QML lint and native package lifecycle checks. It additionally runs the real native replay at 1280x720 and 1280x800, twice per scheme, after a successful build even when CTest fails. Each size keeps its own exit status and raw log. `kde-evidence-<format>` contains the actual producing source/job/environment identities and available failure scenes. The per-callout ledger stays pending independent inspection of all original final PNGs before overlays, differences or close-ups. Every unexplained discrepancy remains outstanding; only the unchanged reference contract's narrow exceptions apply.
